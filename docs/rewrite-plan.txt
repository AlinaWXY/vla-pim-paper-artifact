2. 设计原则
旧版的问题来自两份时序规则：Ramulator 一份，外部仲裁器 sequential_timing.h 又一份。新版每条规则只存在一个地方。
时序只在 DRAM spec 里定义一次。 控制器只调用 check_timing，前端和分析脚本不重新实现任何时序。
GPU 和 PIM 的请求在同一个控制器里竞争。 仲裁就是控制器的调度策略，不存在"先单独跑 PIM、再重放"。
PIM 程序是高层请求流。 控制器把请求展开成命令并跟踪依赖；不从 trace 反推 DQ 延迟。
GPU 访存闭环注入。 内存跟不上时 kernel 自然变慢；单独运行校准是验收标准，之后不做任何常数修正。
验证与决策分离。 DQ/CA 检查插件只断言、不参与调度；spec 写错会在检查插件里立即报错。
开关正交且受校验。 非法组合直接报错；不保留历史兼容开关（旧版 config.py 中 20 多个 pim_* 开关收敛为第 9 节的 5 个）。

4.3 约束派生规则
在 spec 构造时执行一次，不手写任何 WRGB/RDRES 约束：
ALIAS = {"RD": "RDRES", "RDA": "RDRES", "WR": "WRGB", "WRA": "WRGB"}for tc in LPDDR5X.timing_constraints:    if tc.level not in ("Channel", "Rank", "BankGroup"):   # Bank 级不派生；广播命令视为命中每个 BG        continue    if not set(ALIAS) & set(tc.preceding + tc.following):        continue    pre = tc.preceding + [ALIAS[c] for c in tc.preceding if c in ALIAS]    fol = tc.following + [ALIAS[c] for c in tc.following if c in ALIAS]    spec.add(level=tc.level, preceding=dedup(pre), following=dedup(fol),             latency=tc.latency, sibling=tc.sibling, window=tc.window)
派生覆盖所有组合：RD→WRGB、WRGB→RD、RDRES→WR、WR→RDRES、RDRES→WRGB 等，同 rank 与跨 rank（sibling）都有。
Bank 级阵列约束（tRCD、tRTP、tWR、tRAS）只作用于 RD/WR，不派生。WRGB/RDRES 覆盖全部 bank，BankGroup 级约束按"与每个 BG 都是同 BG"处理。
WRGB/RDRES 的 DQ 延迟在 spec 中声明为 nCWL / nCL，控制器和检查插件读同一个值。
4.4 内部命令约束
MAC：Bank 级，ACT2→MAC ≥ tRCD，一列权重与 M 行输入的计算时长 = M × 4/k CK（k = mac_freq_mult）；同一 bank 下一次列读取间隔 = max(tCCD_L, M × 4/k)，MAC→PRE ≥ tRTP；WR→MAC ≥ CWL+BL+tWTR_L。取数与计算流水重叠：计算当前列时可以读下一列，所以只要 M × 4/k ≥ tCCD_L，倍频就直接缩短 MAC 时间。
LOCALRD/LOCALWR：沿用旧版 lpddr5pim.py 第 89–110 行的 Bank 级规则，不占外部 CA、DQ。
MAC_RUN/ROPE_RUN：外部 CA 占用 21 CK，解码 1 CK 不占 CA；展开后的内部命令走 rank 私有 CA。
刷新：REFpb/REFab 按 spec，阻塞对应 bank/rank 的全部命令（含 MAC）。
4.5 命令对矩阵（单元测试的标准答案）
对 {RD, WR, WRGB, RDRES} 两两组合 × {同 BG, 不同 BG, 不同 rank}，由 spec 计算最小发射间隔和对应 DQ 空隙：
DQ\ gap = issue\ gap + latency_{2} - latency_{1} - BL
要求：每一项 DQ 空隙 ≥ 该方向所需的转向间隔，且不出现负值（后发先至）。关键几项的期望值：跨 rank RD→WRGB = 15 CK；跨 rank WRGB→RD = 2 CK（DQ 空隙 11 CK）；同通道 RDRES→WRGB = 15 CK。矩阵以 JSON 存档，作为回归基准。

6. 控制器与仲裁
仲裁是旋钮，但只在 concurrent + streaming 下存在；串行时没有竞争，融合时 DQ 按 epoch 独占、内部命令走私有 CA，调度规则唯一确定，因此不暴露仲裁旋钮。
6.1 每通道控制器结构
两个请求队列：GPU 队列（只访问 rank0）、PIM 队列（只访问 rank1，由 PIM sequencer 填充）。
每个周期：两队列中所有就绪请求的下一条命令，凡能通过 check_timing 的都成为候选；调度策略从候选中选一条发出。
DQ 冲突与转向已经编码在 spec 里，控制器不做单独的 DQ 检查。
行策略：GPU 开页；PIM 由程序显式发出 ACT/PRE。
刷新：按 spec 周期发出，期间两队列都不能向被刷新的 bank/rank 发命令。
GPU 写批处理：写请求进写队列，达到高水位开始排空、降到低水位停止。两个水位是 VLM 校准参数（第 7 节），所有 case 共用。

展开后的内部命令走 rank 私有 CA，不与 GPU 竞争。

7.2 VLM 闭环注入
每个 VLM kernel 的输入：实测时长 T、读字节 R（L2 read miss，实测）、写字节 W（L2 写扇区）。
写回系数 α：实际 DRAM 写 = α × W，全局一个值。
地址：按 kernel 的张量区域顺序生成 32 B 扇区地址，经通道交织映射到 rank0。
发射节奏：请求在 [启动, 启动 + T] 内均匀释放，但每通道在途请求数不得超过窗口 M；窗口满时后续请求等待。内存跟不上时，kernel 自然延长。
kernel 完成 = 最后一个请求完成，且不早于启动 + T。
7.3 单独运行校准（验收标准）
自由参数只有三个：α、M、写批处理的高/低水位。
目标：VLM 单独运行总时长与实测 104.95 ms 相差 ≤ 5%；同时报告逐 kernel 相对误差分布（中位数、p90）。
校准在 concurrent 实验之前完成，参数写入固定配置文件，所有 case 共用。
达不到目标时，先检查 α 是否已到下限，再检查写批处理；不允许回到常数偏差抵消。
8. 阶段驱动与时延记账
阶段驱动只决定"什么时候把哪些请求交给控制器"，所有时延都来自控制器的事件时间戳，不做任何事后归一化。
8.1 AE 静态调度
AE 是一个固定序列：GPU 块（非线性算子，时长取 Thor 实测，不产生 DRAM 请求）与 PIM 阶段交替，共 18 层 × 10 步。PIM 阶段开始 = 前一个 GPU 块结束；GPU 块开始 = 前一个 PIM 阶段结束且 GPU 空闲。
8.2 VLM kernel 放置（固定规则，不设旋钮）
VLM kernel 按依赖顺序，在 GPU 空闲（没有 AE GPU 块在执行）时依次启动。
已启动的 kernel 执行到结束，不被抢占，可以跨越多个 PIM 阶段。
AE GPU 块必须等 GPU 上在执行的 VLM kernel 结束才能开始；等待时间记为 AE GPU wait。
AE 全部完成后，剩余 VLM kernel 独占执行。

11.3 实现顺序与每步退出条件
spec：命令集、内部约束、派生规则、命令对矩阵测试。退出：验证第 1 级通过。
控制器 + 检查插件：双队列、依赖跟踪、刷新、frfcfs。退出：微基准前两项通过，检查插件无断言。
PIM sequencer（streaming）：生成 c/d/e 的程序。退出：5 个配置中 3 个 streaming 的单独运行通过第 4 级。
rank controller + fused：描述符、私有 CA、epoch 规则。退出：f/g 单独运行通过第 4 级。
VLM 注入 + 校准：写批处理、窗口 M、α。退出：第 5 级通过。
阶段驱动 + 记账：AE 调度、kernel 放置、指标。退出：case b 的 total = AE_solo + VLM_solo。
仲裁策略：pim_head、pim_lookahead、gap_batch。退出：微基准第 4 项通过。
完整矩阵：b–g 与仲裁消融。退出：第 6 级通过，输出与 9.3 节格式一致。
